# Sluice v0.4.0

Minor release. Two additive features, no breaking changes. Recommended upgrade for all v0.3.x users.

## Install

```bash
pip install --upgrade sluice-taint
```

PyPI: https://pypi.org/project/sluice-taint/0.4.0/

## Highlights

- **`sluice report`** — per-session summary of what Sluice caught, in `human`, `markdown`, or `json` format.
- **`pseudonymize` action** — a third option for PII beyond `block` and `redact`. Full round-trip: the LLM sees stable placeholders like `EMAIL_A`; Sluice restores real values on outbound tool calls.

Both features are additive. All v0.3.x configs continue to work unchanged.

## What's new

### 1. `sluice report` — see what happened in a session

Sluice's work has been invisible so far. You install it, everything protects itself, you never see the value. `sluice report` turns the existing SQLite audit log into a human-readable summary:

```
Sluice session report — sess-a3f9b2c1
2026-09-18 14:22:03 → 14:47:19  (25m 16s)  •  upstreams: filesystem, github

Summary
  Requests inspected      42
  Sensitive values seen    3
  Actions taken            2 blocked, 1 redacted, 39 passed

Sensitive values (hashes only)
  ab8f…  first seen  14:22  filesystem/read_file
         blocked     14:31  github/create_issue  →  BLOCKED (taint_leak)
  ...
```

Three formats: `human` for the terminal, `markdown` for pasting into docs or blogs, `json` for scripting.

```bash
sluice report                                    # last session, human format
sluice report --session sess-a3f9b2c1             # specific session
sluice report --last 5 --format json              # 5 most recent as JSON
```

Pure read-side over the existing `events` table. No schema changes. Raw secret values never appear in the output — an explicit test guards this invariant across all three formats.

### 2. `pseudonymize` — full round-trip PII substitution

New policy action for PII. When a rule fires with `action: pseudonymize` on a PII hit:

- The LLM sees a stable placeholder like `EMAIL_A` in tool responses
- On outbound tool calls, Sluice substitutes the real value back before the message reaches the tool server
- Same real value gets the same placeholder for the whole session

Example config:

```yaml
policy:
  rules:
    - detector: "pii.*"
      action: "pseudonymize"

pseudonym:
  enabled: true
  fail_closed_on_reverse: true
```

What this unlocks: agents can work with PII coherently (schedule meetings across real contacts, reply to real customers, analyze real datasets) without the LLM ever seeing the raw values. Real values stay on your disk and reach the tool servers; only pseudonyms live in the model's context.

**Design decisions locked in:**

- **Session-scoped.** Fresh registry per session. No cross-session persistence.
- **PII only.** Secrets still go through `redact` in mixed messages so nothing quietly leaks under the guise of pseudonymization.
- **Fail-closed on reverse.** Outbound messages with unknown pseudonym-shaped tokens are blocked by default.
- **Direction-aware.** `pseudonymize` is a response-direction action; on requests it coerces to `flag`.
- **Taint interaction.** Reversed pseudonyms are exempt from taint on the same message so the round trip actually works. Direct PII writes by the AI still fire taint as before.

Full behavior and known limitations: [docs/design/pseudonymization.md](../design/pseudonymization.md).

**Known limitation to understand before adopting:** pseudonyms may appear in the AI's final chat message to the user because that response doesn't pass through Sluice. Real values still reach real tools; only the chat text may reference the pseudonym. This is an architectural consequence of proxying at the MCP layer, not something the feature can fix.

## Small changes shipped alongside

- `ChainedSink.find(cls)` and `ChainedSink.sinks` public helpers, so `report` and `dashboard` no longer reach into the private `_sinks` list.
- `sluice report` now includes a `pseudonymized` action count alongside the existing `blocked / redacted / flagged / passed` breakdown.

## What didn't change

- All v0.3.x configs continue to work unchanged. No schema bump.
- Detector protocol, existing CLI commands, SQLite audit schema all stable.
- Performance: 0.02 ms clean p50 unchanged. Pseudonymize adds one dictionary lookup per PII hit on responses and one regex scan on requests — no measured change to the clean path.
- Existing tests untouched. Full suite: 112 passing (was 62). 50 new tests: 41 for pseudonymization coverage, 9 for the pipeline round-trip, plus the earlier 12 for `sluice report`.
